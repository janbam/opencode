## 1. TypeScript Execution for Development

### Options Comparison

| Option | Pros | Cons |
|--------|------|------|
| **tsx** (recommended) | Watch mode, ESM/CJS bridging, tsconfig paths, fast | External dependency |
| Node native (`node file.ts`) | Zero deps, built-in (Node 22.18+) | No tsconfig support, limited to "erasable" TS syntax |
| ts-node | Mature, tight compiler integration | ESM via loader hooks is finicky, slower than tsx |

### Recommendation: tsx

**Why tsx:**
- Drop-in replacement for `node` with great DX
- Works seamlessly with ESM-first packages (common in AI SDK ecosystem)
- Supports watch mode: `tsx watch src/index.ts`
- Handles tsconfig paths

**Suggested dev scripts:**
```json
{
  "type": "module",
  "scripts": {
    "dev": "tsx watch packages/opencode/src/index.ts",
    "check": "tsc --noEmit",
    "dev:all": "concurrently -k \"tsx watch packages/opencode/src/index.ts\" \"go run ./packages/tui/cmd/opencode\""
  }
}
```

### Node's Native TypeScript

Node 22.18+ runs `.ts` files directly for "erasable" syntax (no flags needed):
```bash
node file.ts
```

For non-erasable constructs (enums, namespaces):
```bash
node --experimental-transform-types file.ts
```

**Note:** Node ignores `tsconfig.json` at runtime; keep `tsc --noEmit` for type-checks.

## 2. Single Executable Creation for Production

### Options Comparison

| Option | Status | Binary Embedding | Notes |
|--------|--------|------------------|-------|
| **Node SEA** | Active development | ✅ Yes (assets API) | First-party, recommended |
| nexe | Maintained | ✅ Yes (-r flag) | Userland alternative |
| pkg (vercel) | ⚠️ Archived | Yes | Use forks if needed |

### Recommendation: Node SEA (Single Executable Applications)

**What it does:**
- Injects a "blob" (bundled script + optional assets) into a Node runtime
- Creates one binary per target OS/arch
- Supports embedding binary files via `assets` map (replaces `Bun.embeddedFiles`)

**Limitations:**
- CJS entry only (not ESM)
- Per-OS/arch injection required
- Not supported on Alpine/musl
- Marked "Active development"

### SEA Build Flow

**Step 1: Bundle TypeScript to CJS**
```bash
esbuild packages/opencode/src/index.ts \
  --bundle \
  --platform=node \
  --format=cjs \
  --target=node22 \
  --outfile=dist/cli.cjs
```

**Step 2: Create SEA config (per platform)**
```json
{
  "main": "dist/cli.cjs",
  "output": "dist/sea.blob",
  "useCodeCache": false,
  "useSnapshot": false,
  "assets": {
    "tui-bin": "dist/tui/linux-x64/tui"
  }
}
```

**Step 3: Generate blob and inject**
```bash
# Generate blob
node --experimental-sea-config sea-config.json

# Inject into Node binary
npx postject opencode NODE_SEA_BLOB dist/sea.blob \
  --sentinel-fuse NODE_SEA_FUSE_fce680ab2cc467b6e072b8b5df1996b2
```

**Step 4: Sign (macOS/Windows)**
- macOS: Remove existing signature, inject, re-codesign
- Windows: Sign with signtool

### Runtime Extraction (replaces Bun.embeddedFiles)

```typescript
// tui.ts
import { getAssetAsBlob, isSea } from 'node:sea';
import { writeFile, chmod, mkdir } from 'node:fs/promises';
import path from 'node:path';
import envPaths from 'env-paths';

export async function ensureTui(binaryName: string): Promise<string | null> {
  if (!isSea()) return null; // Running plain node in dev

  const blob = await getAssetAsBlob('tui-bin');
  const cacheDir = path.join(envPaths('opencode').cache, 'tui');
  const binPath = path.join(cacheDir, binaryName);

  await mkdir(cacheDir, { recursive: true });
  await writeFile(binPath, Buffer.from(await blob.arrayBuffer()));

  if (process.platform !== 'win32') {
    await chmod(binPath, 0o755);
  }

  return binPath;
}
```

## 3. Alternative: Ship TUI Separately

### Pattern: Download on First Run

Instead of embedding, download the TUI binary on first launch. This mirrors how `esbuild` and `sharp` deliver prebuilt executables.

### Implementation

```typescript
import { mkdir, writeFile, chmod } from 'node:fs/promises';
import { createWriteStream } from 'node:fs';
import { pipeline } from 'node:stream/promises';
import { request } from 'undici';
import crypto from 'node:crypto';
import path from 'node:path';
import envPaths from 'env-paths';

async function ensureTui(version: string, binName: string): Promise<string> {
  const cacheDir = path.join(envPaths('opencode').cache, 'tui', version);
  const exe = path.join(cacheDir, binName);

  // Check if already cached
  try {
    await chmod(exe, 0o755);
    return exe;
  } catch {}

  await mkdir(cacheDir, { recursive: true });

  // Build download URL based on platform/arch
  const platform = process.platform;
  const arch = process.arch;
  const url = `https://github.com/sst/opencode/releases/download/v${version}/tui-${platform}-${arch}.tar.gz`;
  const expectedSha256 = lookupChecksum(version, platform, arch);

  // Download
  const res = await request(url);
  const tgzPath = path.join(cacheDir, 'tui.tgz');
  await pipeline(res.body, createWriteStream(tgzPath));

  // Verify checksum
  const buf = await readFile(tgzPath);
  const sha = crypto.createHash('sha256').update(buf).digest('hex');
  if (sha !== expectedSha256) {
    throw new Error('Checksum mismatch');
  }

  // Extract and set permissions
  // ... (use tar library or system tar)

  if (process.platform !== 'win32') {
    await chmod(exe, 0o755);
  }

  return exe;
}
```

### Comparison: SEA vs Separate Download

| Aspect | SEA + Embedded | Separate Download |
|--------|----------------|-------------------|
| Distribution | Single file | Multiple files |
| Build complexity | Higher | Lower |
| First-run experience | Instant | Requires network |
| Update flexibility | Full release needed | Can update TUI independently |
| npm package size | Larger | Smaller |
| Alpine support | ❌ No | ✅ Yes |

### Helpers

- `env-paths`: OS-specific cache directory
- `@xhmikosr/bin-wrapper`: Maintained fork for binary downloading

## 4. Build Toolchain

### TypeScript Bundling

**Recommendation: esbuild**

```bash
esbuild packages/opencode/src/index.ts \
  --bundle \
  --platform=node \
  --format=cjs \
  --target=node22 \
  --outfile=dist/cli.cjs
```

**Why esbuild:**
- Stable, very fast
- Perfect for bundling CLI to single CJS file for SEA
- Handles ESM/CJS dependencies well

**Alternatives:**
- `tsdown`: Rolldown-based, successor to tsup (for libraries)
- `tsup`: Now in maintenance mode, consider tsdown instead

### Go TUI Builds

Keep existing cross-compilation:
```bash
CGO_ENABLED=0 GOOS=${os} GOARCH=${arch} go build \
  -ldflags="-s -w" \
  -o dist/tui/${os}-${arch}/tui \
  ./packages/tui/cmd/opencode
```

**Consider GoReleaser** for:
- Per-OS/arch artifact generation
- Homebrew/AUR metadata
- macOS signing/notarization

### Cross-Platform CI

GitHub Actions matrix for:
- `linux-x64`, `linux-arm64`
- `macos-arm64`, `macos-x64`
- `win32-x64`

**Important:** For SEA, inject blob on same-platform runner. Don't enable code cache/snapshot for cross-platform blobs.

**Note:** SEA not supported on Alpine—offer tarballs or use separate download approach.

## 5. Package Manager Migration

### Bun Workspaces → pnpm Workspaces

**Step 1: Create `pnpm-workspace.yaml`**
```yaml
packages:
  - 'packages/*'
```

**Step 2: Update dependencies**
```json
{
  "dependencies": {
    "@opencode/shared": "workspace:*"
  }
}
```

### Bun `catalog:` → pnpm `overrides`

**In root `package.json`:**
```json
{
  "pnpm": {
    "overrides": {
      "typescript": "5.8.2",
      "@types/node": "22.13.9",
      "zod": "3.25.49",
      "ai": "5.0.0-beta.18"
    }
  }
}
```

### ESM Compatibility

For AI SDK ecosystem compatibility:
- Use `"type": "module"` in package.json
- For dev runs, `tsx` handles ESM/CJS edge cases
- For SEA entry, bundle to CJS with esbuild

## Complete Build Workflow

### Track A: Single Binary (SEA + Embedded TUI)

```bash
# 1. Build Go TUI per OS/arch
for os in linux darwin windows; do
  for arch in amd64 arm64; do
    CGO_ENABLED=0 GOOS=$os GOARCH=$arch \
      go build -ldflags="-s -w" \
      -o dist/tui/${os}-${arch}/tui \
      ./packages/tui/cmd/opencode
  done
done

# 2. Bundle TS to CJS
esbuild packages/opencode/src/index.ts \
  --bundle --platform=node --format=cjs \
  --target=node22 --outfile=dist/cli.cjs

# 3. Create SEA config (per platform)
# 4. Generate blob: node --experimental-sea-config sea-config.json
# 5. Inject: postject ...
# 6. Sign (macOS/Windows)
```

### Track B: Split Delivery (Download TUI on First Run)

1. Publish `opencode` CLI to npm (JS only)
2. On first run, detect OS/arch, download TUI from GitHub Releases
3. Verify checksum, cache in `env-paths('opencode').cache`
4. For Homebrew/AUR, point formula/PKGBUILD at platform TUI tarballs
